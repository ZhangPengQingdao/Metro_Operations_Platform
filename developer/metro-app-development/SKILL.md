# 运管平台应用开发

使用随包 references 中对应版本的规范。若目标平台版本不同，先取得该版本开发者资料；应用开放接口目录是时间点快照，不能作为持续授权证明。没有已验证的接口契约时询问提供方，不猜接口或导入平台内部源码。

## 新建应用

阅读 references/start.md，确认业务目标、应用ID、发布者、目标平台版本和权限范围。优先以 standard 模板建立真实沙箱与隔离后端链路。根据任务按需阅读下面的参考，再实现与验证。

## 改造已有应用

先阅读 references/migration.md。全面梳理项目结构、业务模块和关键调用链：身份、角色、数据、路由、外部调用、文件、任务、构建部署与测试；跳过依赖、构建产物和凭据。保留用户原有修改。

形成“原能力→平台能力→保留/替换建议→影响→待确认”清单。结合 references/platform-sdk.md 和当前安装接口快照，判断真正可用的公共能力。不要把目录项、内部模块或清单类型当作已经开放的运行能力。

把身份映射、后端/数据库保留方式、数据迁移、角色范围、业务语义和拟开放接口方案交用户确认。用户已明确的选择无需重问；缺少关键答案时只继续不依赖该答案的工作，不自动选择破坏性迁移。

按已确认方案逐条打通业务链。不要顺手重写无关业务，也不要把改造授权扩大为生产安装、授权或部署。

## 按需参考

- 公共目录、存储、通知、AI、签字、调用方式及限制：references/platform-sdk.md。

- 推荐组件、QueryList、主题、标准侧栏、路由和图标：references/ui-navigation.md。
- 托管数据、原件附件、照片、Excel 解析/生成/下载：references/storage-files.md。区分本地解析与上传存放；Word/PDF 原件支持不代表提供正文解析、生成或 OCR。
- 全部 SDK 导出入口与兼容元数据边界：references/sdk-modules.md。
- 消费或提供业务接口及负责人开放：references/open-interfaces.md。
- 构建目录、图标位置、签名、安装包、升级：references/packaging.md。
- 通知公共能力：references/notifications.md。

## 完成标准

独立目录中能安装公开 SDK/CLI、测试、构建、validate。检查权限拒绝、跨组织访问、路由访问、撤权和未知写入结果。对UI在真实标准沙箱验证点击、主题和窄屏。接口示例与声明一致；角色和权限说明完整。

有用户安全提供的发布者密钥路径才签名；没有密钥时交付已校验构建目录和具体签名命令，不索取聊天中的私钥、不伪造完成。最终报告构建产物/安装包位置、所需管理员及负责人配置、已通过和未执行的验收，以及剩余阻碍。
