# 慧策通·计划督办

独立应用，当前源码版本 0.4.0。采用员工业务授权、隔离后端、平台托管存储及标准沙箱页面，不依赖旧仓库。版本变化见 [更新日志](CHANGELOG.md)。

平台最低版本为 0.25.0（包含同工作区看板接入）。本次升级追加 `migration-003.json`，增加计划原话、最新进展、进度履历和照片私有表；不修改前两份迁移、不迁移生产数据。已有完成状态保持不变，旧进度备注仍保留在计划备注及原审计中，新版开始逐次记录履历。


工作台摘要按现有 read 授权范围统计全部月份条目，排除取消记录，提供完成统计、每日新增趋势和精简预览；口径与平台个人布局见 [工作台接入说明](../../docs/employee-dashboard.md)。

## 1.0.0：应用模型 v2

本版改为 v2 项目，作为新应用安装（不保留旧版测试数据）：`app.json`、`icon.svg`、`src/`（页面 `ui.jsx`、样式 `ui.css`、接口 `server.js` 及业务模块）、`migrations/`。页面用 `defineApp` 直接渲染在平台内，标题与侧栏由平台按 `pages` 生成；后端在平台子进程中运行。页面：`/` 计划提报、`/bindings` 基础配置。

```sh
npm test            # 业务规则测试
npm run check       # 校验 app.json、迁移与页面/接口一致性
npm run build       # 输出 dist/huicetong-1.0.0.mopkg
```

要求平台 0.30.0 及以上。管理员上传 `.mopkg` 安装后指定应用负责人，负责人配置角色与使用人员。以下为各版业务说明，涉及签名包、沙箱和 `build.mjs` 的构建与安装步骤已不再适用。

## 已实现

- 宿主侧边栏只有“计划提报”(`/`，`read`) 与“基础配置”(`/bindings`，`manage`)。平台服务端按路由权限过滤侧边栏。组织默认取会话中第一个授权组织，不提供手动组织切换；月份在计划筛选区选择，默认当前上海时间年月，未有计划的月份不显示周期提示。
- 填报人编制和修改草稿，填写质量标准、时间、拟提报标记及至多 6 位责任人，并指定一位牵头人；新月份首次填报时在条目事务内懒创建唯一 drafting 周期，普通填报人无需 `manage`。`item-create` 继续兼容 `cycleId`，新入口传 `{organizationId,year,month}`；并发唯一性冲突仅在确定未写入时重新读取已创建的周期。
- “提报计划”先输入一句话，通过平台 AI 生成计划内容、可验收的质量标准、分类和日期建议。整理后进入可编辑的确认页，再选择责任人、补齐日期并点击“确认提报”；缺失信息按需展开。AI 不生成责任人身份、不自动提交；不可用时继续手工录入。原话随计划保存。提报与确认分步展示，责任人使用搜索多选；备注和其他选项按需展开。
- 责任人或管理岗通过“跟进提报”记录本次进展、问题、下一步和证明材料。每次进度追加独立履历，不覆盖计划原备注。照片（每次最多 6 张）随进度事务关联；Word、Excel、PDF、ZIP 原件通过宿主附件通道上传，每份最多 50 MiB，直接关联已存在的计划，关闭弹窗仍保留。
- 状态流程为 `draft → in_progress → pending_confirm → completed`。责任人或管理岗可从待开始/进行中提报完成，由所辖二级分类绑定的归口人（`review`）或目标组织管理人员（`manage`）确认办结。管理人员无需同时具有 `review` 或归口绑定。退回必须填写意见，回到进行中；再次提报保留历史。不增加禁止兼任人员自审的规则。
- `item-progress` 的旧入参 `completed` 兼容映射为 `pending_confirm`，不能绕过办结。待办结及终态不允许直接更新进度或继续上传文档；办结和退回都核对条目版本及月度容器状态，状态写入、履历、照片关联、审计同事务完成。取消沿用原有责任人/管理人员规则，不等同完成办结。
- 履历和材料只向有该计划读取权限的员工开放；归口确认由服务端核对组织、授权和分类绑定，已停用分类的历史计划仍可办结。归口或管理人员在“查看并办结”中查看完成说明和材料后确认或退回。
- 通过平台人员目录核验在岗责任人及所属组织；服务端按员工业务权限和组织范围复核读写。
- 提报、归口配置、分类字典和汇总弹窗统一使用 L2 QueryList，搜索默认收起；新增计划与搜索、筛选、功能菜单同排。当前授权组织及月份位于筛选弹层，月份确认后生效，取消不改变上下文，重置保留组织与月份。提报每页 20 条，通过游标翻页，搜索/分类/状态筛选作用于当前页；汇总读取完整月份计划，可搜索并导出 xlsx。
- 计划功能菜单固定保留汇总预览和导出 xlsx，无月度周期、读取中、保存中或写入待核对时禁用导出；无周期时提示原因。计划及配置页不提供刷新功能项，保存后的自动重新读取仍保留。
- 基础配置维护二级分类归口人和三级分类字典；分类“停用”代替物理删除，保留已有计划快照。沿用宿主画布与即时主题切换，筛选、菜单和表单下拉适配暗色与窄屏，错误显示在当前弹窗内，保存中及结果未知时禁用写入。
- 周期、分类和条目写入附带审计事件；条目编辑使用版本比较，周期状态与条目写入在同一事务校验。未知写入结果不自动重放。

旧 M2 后端继续保留编制归口审核、条目提交、周期送审/退回/签发/锁定、锁定后变更复审与负责人追认；0.3.0 前端不展示这些流程。周期签发仍采用**负责人应用内确认+审计**，待平台签字板就绪后完善；周期退回通知暂仅记录待发审计事件。

导出由服务端生成 xlsx 并记审计，沙箱通过 `downloadSandboxFile` 下载；宿主附件 SDK 的业务原件上传入口仅接受用户本地 `File`，尚无后端生成原件登记接口，因此导出件尚未做附件登记/授权下载（员工上传的证明原件已接通）。清单声明 `ui.downloads: true`，服务端按读权限与组织校验后返回文件；受 Bridge 响应大小限制，单次 xlsx 不得超过 40 KB，大周期会明确报上限错误。页面从当前员工所在工班选择责任人及归口人；后端支持同部门跨工班，跨工班选择界面仍需补足。

规划书附录 A 只有分类树，没有提供 9 月 33 条原始电子表格；当前不能宣称与原表逐列人工核对完成。导入 TSV、督办登记、月度归档仍属于后续里程碑；本版本已补齐日常进度与材料交账、归口/管理办结。

## 授权与构建

安装时为应用服务审批 `platform.app_data.read`、`platform.app_data.write`、`platform.people.read`、`platform.ai.complete`、`platform.attachments.create`、`platform.attachments.read`；为员工授予 `app.huicetong.read`，填报人与责任人授予 `fill`，配置岗授予 `manage` **及** `read`（代管计划还需 `fill`），归口办结人员需 `review` 及 `read`，并配置二级分类归口绑定；管理办结人员需 `manage` 及 `read`，无需 `fill`。旧签发接口仍需 `sign`。升级时需重新审批新增服务权限，AI 还需平台配置模型。各项部门级权限限定在实际计划组织；不以普通员工身份替代负责人身份。安装、审批及授权按 [应用接入](../../docs/applications.md) 进行。

```sh
npm run build:sdk
npm --prefix applications/huicetong test
npm --prefix applications/huicetong run build
node packages/platform-cli/dist/cli.mjs validate applications/huicetong/dist
npm run version:check
```

构建产物在 `dist/`，由 `build.mjs` 生成清单、前后端包和初始迁移。应用单独管理版本，不执行平台根目录的 `version:bump`（该脚本用于平台/SDK/CLI 同步升版）。本次仅构建、校验，不签名、不部署；本源码不含私钥或生产数据。

## 新接口与验收

- `plan-suggest`：`{organizationId,month,rawText}`，校验填报权限，返回待确认字段建议，无业务写入。
- `item-workflow`：`{id,after?}`，返回当前计划、每页 20 条进度及 `canUpdate/canClose`，范围跟随源计划。
- `item-progress`：`{id,requestId,expectedVersion,status,remark,photoIds?}`，状态支持进行中、待办结或取消；旧 `completed` 转待办结。
- `completion-review`：`{id,requestId,expectedVersion,action:'confirm'|'return',comment?}`，归口或管理办结；退回意见必填。
- `authorize-attachment`：宿主调用的原件授权；`photo-begin/part/finish/read`：公开照片 SDK 对应的业务接口。

原件按计划关联，照片按具体进度关联。完成说明必须填写，是否有足够材料由办结人判断，不强制每条计划都上传文件。未保存进度的临时照片不展示为已提报材料，暂无自动回收任务。附件上传结果未知时只按 `intentId` 查询核对，不自动重放；仍无法确认则显示请求编号并阻断后续写入。记录未知写入同样保持阻断，由管理员结合请求编号核对后处理。

本地回归覆盖手工及 AI 建议、缺失信息、AI 不可用、进度历史、完成提报、归口/管理办结、退回重报、跨组织与非责任人拒绝、并发冲突、照片归属及附件授权。上线后还需验证实际模型配置、宿主附件存储及升级审批；本地模拟模型结果不代表真实模型输出质量。
