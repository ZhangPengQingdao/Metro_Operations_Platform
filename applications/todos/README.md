# 待办事项应用

独立应用 `todos` 通过公开 SDK 接入开放平台。功能按原系统的任务、子项和周期模板组织：普通任务按工班发布，可选择车站或本工班人员作为目标；每个目标有独立完成状态与办理备注。周期模板按上海时间每天、每周或每月生成任务，页面提供启用、停用、编辑、删除和手动生成。任务支持可选截止时间及分值；本版不含督办、党员示范或旧库数据迁移。

页面使用共享 L2 筛选栏、列表、日期与时间选择器；筛选和搜索入口位于列表右侧，点击搜索图标才展开输入框，发布入口也在筛选栏。任务行打开详情弹窗查看及办理子项，车站子项可指定本工班完成人。人员、车站选择区紧跟分配方式，复用 L2 标签选择器并在打开表单时直接展开；标题行可收起，下面直接是搜索、全选、清除和目标标签，不另开浮层。表单勾选项、单选下拉菜单及任务和周期模板列表的图标文字操作均使用 L2 组件；车站目录可按需加载下一页。

## 构建与安装

在仓库根目录运行：

```sh
npm --prefix applications/todos test
npm --prefix applications/todos run build
npm --prefix server run app-cli -- validate ../applications/todos/dist
```

`dist/` 是待签名目录。按 [应用接入](../../docs/applications.md) 的 CLI 流程签名、验签、导出上传包，经管理端预览、批准并安装，再配置应用使用授权、业务角色和服务身份授权。安装后核对授权和运行状态。本仓库不存放发布私钥或签名上传包。

平台需启用托管存储并为此应用服务身份授权 `platform.app_data.read`、`platform.app_data.write`、`platform.people.read` 和 `platform.locations.read`。人员目录按工班读取，车站目录按平台车站读取。业务角色必须先有 `app.todos.read` 作为页面及 API 基础权限，其他操作权限按需要添加：

| 权限 | 用途 | 推荐范围 |
| --- | --- | --- |
| `app.todos.read` | 查看待办、任务详情 | 工班、部门或指定工班 |
| `app.todos.create` | 发布普通任务 | 工班、部门或指定工班 |
| `app.todos.handle` | 办理子项 | 工班、部门或指定工班；人员目标仅本人办理 |
| `app.todos.manage` | 编辑、删除任务；可办理本范围子项 | 工班、部门或指定工班 |
| `app.todos.recurring` | 管理和手动触发周期模板 | 工班、部门或指定工班 |
| `app.todos.score` | 新建或变更计分任务和模板 | 工班、部门或指定工班 |

检修工可授予 `read + create + handle` 的本工班范围；工班长增加 `manage + recurring + score`。需要管理本部门所属工班时，在平台新建角色并给上述权限选择部门范围即可，不需要内置全局待办管理员。操作和数据范围由后端按每次调用的可信员工授权校验；前端菜单仅辅助展示。

## 业务边界

- 目标数量不设固定上限；平台单次托管事务有 16 KB 请求大小限制，内容或目标过多时会明确提示缩减后提交。办理备注最多 100 字。
- 车站任务的子项可由具备对应工班 `handle` 权限的人办理，并可选本工班人员作为完成人；人员任务仅目标本人或具备 `manage` 权限的人办理。记录实际办理人，不依赖前端传入身份。
- 编辑任务仅修改标题、说明、截止时间与计分信息；目标分配需通过新任务设置。删除为状态标记，已生成的任务不受模板删除影响。
- 周期扫描每分钟执行一次。当天触发时间后至当日结束会生成至多一条任务；停机错过整天不会补造历史任务。数据库唯一索引约束模板与发生日期，防止并发扫描重复生成。自动生成使用模板和发生日期派生的固定写入请求号；结果未知时当前进程暂停该次生成，重启后的相同请求号仍受平台写入记录保护。手动生成按请求号去重。
- 月周期可选择 1～31 日；当月没有指定日期时不会生成。截止日在较短月份按月末计算。周期任务的目标以生成时保存的模板快照为准。
- 读失败提示刷新；写入结果未知时页面阻止继续写入，并要求先核对现有记录，不自动重放。

应用自身的单元测试覆盖工班与部门权限、本人范围、计分权限、人员本人办理、车站完成人、超过 20 个目标、任务版本冲突、周期触发和去重。0.1.3 修复本人范围跨工班目录与办理检查、标准沙箱下保存按钮的点击提交，并对人员和车站目录提供搜索。实际员工授权、Docker 运行及真实托管存储需在目标环境验收。
