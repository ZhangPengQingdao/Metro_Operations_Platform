# 物料管理应用（试装版）

独立业务代码只依赖 `@metro/platform-sdk`。本目录没有旧 AFC 源码引用、平台内部导入或数据库连接；不迁移旧数据。

已实现业务服务、沙箱表单/列表、隔离 Node 后端入口及声明式迁移：

- 物料名称、SKU、单位；新建库存为零，库存变更必须通过入出库流水。
- 同组织 SKU 唯一；操作组织、操作人来自平台可信员工上下文，不接受 payload 覆盖。
- 首版数量为正整数，以物料单位计量，库存范围 0～2147483647；不接受小数或隐式四舍五入。
- 入库、出库使用库存版本比较更新，与流水插入组成同一事务。并发冲突交还调用者，不自动重放。
- 原流水不可修改或删除；冲销增加关联流水，冲销入库不能导致负库存；已冲销流水和冲销流水均不能再次冲销。唯一冲销标记和库存更新同事务写入。
- 库存和记录列表按可信员工组织过滤，支持分页；库存名称搜索、记录按物料筛选。
- 未知写入失败不自动重试。

`npm test` 运行规则测试。平台测试另以 PGlite 执行声明式迁移及 SQL 事务，验证流水失败回滚库存。这些测试不替代实际托管存储、Docker、浏览器或安装验收。

构建：`npm run build` 输出首版 dist；`node build.mjs --upgrade` 输出 dist-upgrade（0.1.1，新增可空规格字段）。使用独立 CLI validate/sign/verify/export-upload 导出 JSON 安装包，私钥不随应用分发。测试已覆盖签名、上传格式导入再验签及追加迁移兼容性。页面遇到未知写入停止继续写入并保留请求编号，不自动重试。

## 工班权限与设置

- 工班长：平台管理员分配工班长角色，并配置 `app.materials.read`、`app.materials.outbound`、`app.materials.manage`。只有工班长有应用侧边栏「设置」入口。
- 普通成员：分配检修工角色，配置 read/outbound；可以查询本工班库存/流水、出库，且只能冲销本人出库记录。
- 物资管理员：工班长在「设置」查询在职本工班成员并任命/撤销；具有建档、入库和入库纠错权限，不能进入设置或再次委任。原员工角色不变，仍需平台授予使用应用及 read/outbound 权限。
- 任命与撤销保留独立审计。设置采用 revision 比较避免覆盖他人修改。入库事务同时锁定并比较委任记录，撤销已提交后旧授权不能再写入库存。
- 工班长身份由宿主实时校验的权限决定，不依赖岗位名称、前端菜单、请求正文或应用存储自封身份。宿主在每次存储请求及提交前复核权限快照。
- 员工离职/停用/调离导致原工班身份不再有效；跨工班任命拒绝。

平台需运行本工作分支的 0.3.0 及新增迁移 MIG-059～062。生产资源域、受限存储管理账号与真实 Docker 安装升级全链路仍未验收。不得把规则测试和签名导出当作生产上线证明。
