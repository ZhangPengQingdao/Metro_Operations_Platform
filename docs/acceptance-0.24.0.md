## 浏览器交互

本地浏览器加载真实开发者中心组件，使用模拟管理员接口数据验证五个栏目、SDK 搜索、已开放/候选切换、缺失契约提示、契约展开、指南和五项下载。检查明暗主题、390px 窄屏及横向溢出。下载交互使用本地实际生成的文件；服务端认证和文件完整性另由接口测试覆盖。

标准示例的真实构建前端放入带 CSP 的 opaque sandbox iframe，使用模拟宿主 Bridge 验证握手、人员列表、展开搜索、搜索参数及窄屏布局。本项不等于真实容器安装后的端到端验收。

## 能力目录与 L2 补充验收

SDK 和应用接口两个栏目使用共享 FilterBar，搜索默认收起；分类/开放状态在确认后生效，取消丢弃草稿，功能菜单承载刷新和导出。浏览器验证附件分类、搜索叠加、清除、筛选确认/取消，以及已开放、全部、未开放候选三种接口范围；390px 暗色布局无横向溢出。

新增公开 app-spreadsheets 入口，平台表格工具共用同一实现。文件、附件、表格及目录定向测试 27 项通过；验证分发模块在无仓库依赖的临时目录生成 Excel 后读回首表和工作簿，中文与公式样式文本保持原值，危险下载路径被拒绝。目录测试对照 package exports 覆盖全部 17 个入口，并核对文件/图片/表格公开函数，避免新增能力漏列。

实际 SDK tgz 解包到独立临时目录后，Excel 生成与解析往返通过。浏览器拦截下载触发并核对导出的 JSON：43 项能力、17 个模块，含附件和 Excel；此次导出检查未重复真实磁盘下载。

目录列出 43 项能力，分别标明本地执行、宿主通道、后端服务或构建阶段。Word/PDF/ZIP 原件存放不宣称提供通用正文解析、文件生成或 OCR。SDK、离线文档和 Skill 的文件指南与入口列表同步生成。

## 发布后验收

管理员检查开发者中心与五项下载；应用负责人核对已开放接口。旧应用未声明 documentation 时应显示“未提供契约”，需要应用发布者补充真实契约并提交新的签名包。新增或修改输入输出结构后，负责人重新确认开放。

使用正式测试员工和已授权应用验证站内通知发送、指定收件人可见、应用内跳转及已读；确认签字提醒仍由签字业务状态控制。本地验收阶段尚未执行生产部署、真实 Docker 安装、生产通知发送或生产权限变更；后续生产发布结果见文末补充。
