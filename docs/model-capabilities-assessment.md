# 平台模型能力扩展评估

2026-10-31。本文是基于当前代码和业务场景的规划建议。已交付聊天、向量、重排序与 ASR 配置及诊断；其余规划不表示业务能力已经上线，也不作为部署或外发业务数据的授权。

## 当前能力与本次交付

平台 1.8.0 的「个人中心 → 系统设置 → 大模型配置」提供「聊天模型」「知识库向量模型」「重排序模型」「语音识别模型」四个标签。独立填写、测试与保存，标签间切换保留本次打开设置期间的表单草稿和结果。保存留在当前页，不触发另一类配置保存。关闭设置或切换左侧设置分类会结束本次模型编辑，不持久保存未提交草稿。测试和保存期间禁止切换标签、左侧分类及关闭对话框。

现有业务调用保持不变；新增配置与诊断见 [模型服务设置](model-service-settings.md)：

- `server/src/core/integrations/ai/` 与 `embeddings/` 独立管理聊天和向量配置；密钥留在平台后端。
- `server/src/platform/knowledge/index.ts` 的 `similar` 检索在全部索引就绪后按余弦相似度排序，默认返回 5 条、最多 20 条；无重排序阶段。`exact` 为受保护名词逐字匹配，不应被重排序截断。
- `applications/huicetong/src/speech-transcriber.mjs` 使用浏览器 `SpeechRecognition` / `webkitSpeechRecognition`；录音由 `audio-recorder.mjs` 处理。已有录音与转写交互，但未提供平台统一 ASR 服务。
- 知识库目前是逐条结构化文本，尚未提供文档解析、分页切分与图片检索。公开网关是有界 JSON 传输，新增音视频能力需要附件引用或单独受控流式传输，不能把整段音频 base64 塞入现有请求。

## 建议覆盖范围

优先级是本项目判断，不代表通用模型排名。每项上线前都需真实业务样本验收。

| 能力 | 本项目收益 | 优先级与边界 |
| --- | --- | --- |
| 重排序 Rerank | 改善计划示例、制度问答的候选排序 | 优先验证；只处理已授权候选，保留精确名词检索 |
| 语音识别 ASR | 巡检口述、故障描述、会议和交接班录音转写 | 优先接入；先录音文件转写，再考虑流式识别 |
| 文档解析 / OCR | 扫描制度、工单、表格入库，保留页码与段落引用 | 优先规划；要连通文件授权、解析、切分和索引 |
| 视觉理解 VLM | 设备铭牌、现场图片描述、图文问答 | 与文档能力一起规划；结果供人工核对，不作为设备安全判定 |
| 语音合成 TTS | 对话朗读、操作指引、交接提示 | 建议提供可选能力；先按需播放，不直接接管运营广播 |
| 多模态向量 | 文字找照片、图纸与图片相似检索 | 图片知识库形成后接入，需独立索引版本与类型 |
| 内容审核 / 敏感信息识别 | 请求外发前识别敏感字段、检查输出 | 按数据治理需求引入；确定字段优先规则脱敏，模型不替代权限 |
| 分类 / 信息抽取 | 工单分类、故障归类、从叙述提取字段 | 先复用聊天模型的结构化输出与校验；规模上来再评估专用小模型 |
| 时间序列预测 / 异常检测 | 客流、能耗、设备状态与故障预警 | 独立平台能力或业务应用，先具备时序数据、基线和持续评估 |
| 优化求解 | 排班、检修计划与资源调度 | 更适合约束求解器，不应包装成聊天模型；需明确业务约束 |
| 图像 / 视频生成 | 培训、宣传素材 | 后置，当前运管主流程收益有限 |

OCR 不等于完整文档解析。扫描页还涉及版面顺序、表格结构、页码、段落与引用映射；可以选择专用流水线，也可以使用支持文档理解的视觉模型。PaddleOCR 的 [PP-StructureV3 官方文档](https://www.paddleocr.ai/main/en/version3.x/pipeline_usage/PP-StructureV3.html)展示了多组件文档解析方式。

## 接入顺序和验收门槛

### 1. 重排序与 ASR

**重排序**：先在当前检索链路内增加可选第二阶段，扩大授权范围内的候选集，再输出原有 `limit` 条。候选规模可从 20–50 条做试验，不能先截到最终 5 条再期望找回漏召回条目。重排序只调整已有候选，无法修复初次召回缺失；是否需要文本与向量混合召回应独立评估。配置与向量模型分开，切换重排序模型通常不需要重建向量索引；分数与向量相似度不同，不复用 `minScore` 阈值。启用后故障应明确返回错误或标记经定义的降级结果，不静默改变排序契约。参考 [Sentence Transformers 检索与重排序文档](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)。

验收：使用真实查询和人工相关性标注比较 Recall@K、MRR / nDCG、P95 延迟及每次成本；包含专有名词、短查询、空候选、跨组织拒绝、重复或越界返回索引、取消和超时。收益未证实时默认关闭。

**ASR**：先把慧策通录音文件接入平台统一转写，返回文本和可用时间戳；说话人区分、热词、实时输入作为服务支持项分别声明。转写内容可编辑，业务提交继续人工确认。首期无需改动现有文本 Agent 编排；后续语音交互可采用「ASR → 已有文本智能体 → 可选 TTS」，专用语音接口与实时音频会话的实现边界不同，见 [官方音频接口概览](https://developers.openai.com/api/docs/guides/audio)。

验收：用中文运管术语、站名、设备编号、现场噪声、不同录音格式测字错率和关键字段准确率，并验证长录音限制、取消、失败查询、附件越权与删除策略。不能承诺浏览器或供应商支持就等于实际可用。

### 2. 文档解析和视觉理解

先建立「授权附件 → 文档解析 → 分页与切分 → 向量索引 → 来源引用」链路，再扩展图文问答。复用附件 ID，平台解析可访问对象；禁止应用提供任意远程 URL 让平台下载。支持视觉的聊天模型可复用服务配置，通过能力声明控制输入格式，不必为同一个模型重复存密钥。专用 OCR 服务则单独配置适配器。

验收：扫描页、横向表格、多栏、旋转页、空白页、损坏文件与解析限额；页面引用能定位原文，删除/撤权后无法继续取回正文。图片生成的描述不能冒充原始文字或检查事实。

### 3. TTS，再按需求扩展多模态检索

TTS 首期提供文字朗读、音色、格式、语速和停止播放。音频应继承原文访问范围，若缓存需绑定内容版本、模型、音色与授权范围。验收中文术语读音、首段延迟、长文本上限、播放取消、音频格式、访问控制和生成成本。实际音色与格式以适配器能力为准，参见 [TTS 官方接口说明](https://developers.openai.com/api/docs/guides/text-to-speech)。

图片知识库形成之后，再对多模态向量、图片近似检索做专项验收；不要把图像向量直接混入现有文本向量索引。

## 平台接入原则

1. **按能力建立契约，按服务保存配置。** 后续形成服务连接、能力绑定、默认模型和能力专有参数三层；同一服务可以支撑聊天、视觉或语音，配置界面仍按使用目的分标签。本次沿用聊天与向量配置，追加独立的重排序与 ASR 配置，避免为未来能力立即重构。
2. **配置和业务启用分阶段交付。** 按当前需求先交付「重排序」「语音识别」配置和真实诊断，页面明确尚未接入业务；后续补齐检索和语音调用、质量验收后再开放启用。语音合成、文档与视觉仍保留在规划中。
3. **能力适配器负责协议差异。** 聊天、向量、重排序、音频、文档处理的协议并不相同；“OpenAI 兼容”只能标记已验证的能力范围。模型列表并不能证明某模型支持语音或视觉。
4. **应用通过公开 SDK 使用。** 新操作须补充清单权限、契约、网关适配与文档，平台绑定应用、员工和组织；附件读取独立核验，不向应用暴露供应商密钥或管理员会话。
5. **复用平台边界。** 加密配置、管理员审计、精确内网地址允许列表、超时、取消、并发和费用限额；平台写入采用事务与 requestId，外部调用失败不自动重放。异步任务按请求标识查询结果。
6. **可选启用，可观测。** 记录能力、模型版本、耗时、用量与错误码，默认不记录密钥或完整敏感音频/正文；未配置与调用失败必须区分。已启用能力只有经过明确契约才能降级。

本次新增配置存储、管理员诊断接口和幂等记录迁移；没有选择供应商、下载权重、部署模型服务、开放业务调用权限或变更 SDK。具体模型和部署方式应由真实评测、数据边界、硬件、许可与成本共同决定。

## 初始标签拆分阶段验收

- 前端 `npm run typecheck`、`npm run build`（包含 SDK、CLI、开发者资源）、后端 `npm --prefix server run build` 通过。
- `admin-console`、`knowledge-vectors`、`frontend-core`、`versioning` 四组相关测试共 14/14 通过；版本一致性和 diff 空白检查通过。
- 生产前端构建配合浏览器拦截的受控 API 响应验证：默认只展示聊天表单；切换保留两侧模型及密钥草稿；获取模型、测试成功/失败；保存只调用本类接口并清空本类密钥输入；空密钥不随保存发送；聊天保存不关闭设置、保留另一页草稿；测试期间锁定标签、侧栏和 Escape 关闭；Home/End/左右键切换。
- 检查桌面 1440px、窄屏 390px 与 320px，确认内容可滚动且对话框无横向溢出；检查明暗主题。浏览器脚本、结果与截图保存在本地忽略目录 `output/playwright/model-settings-*`，验收期间未修改真实模型配置，也未调用真实供应商。
- 自查范围：表单状态隔离、保存边界、忙碌恢复、可访问性、共享主题与文档一致性。该阶段未修改后端接口、数据表和权限；随后追加的重排序/ASR 配置验收另见模型服务设置文档。
