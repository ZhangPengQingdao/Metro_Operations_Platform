# 测试与验收

## 开发机器上的检查

```sh
npm test
npm run check
npm run build
```

模板用 Node test 和假 gateway 测真实 handler，示例在 `test/server.test.js`。`check` 检查 app.json、参数示例、源码入口和迁移结构；`build` 生成 `.mopkg` 并验证打包内容。二者不会替代业务行为和线上权限测试。

## 按改动选择测试

查询接口验证正常结果、空结果、非法参数、本人/工班/跨组织范围和分页。先过滤权限再分页，避免泄漏总数或漏掉本页应可见记录。写接口验证 requestId 重试、并发 expected 冲突、无权限和无效数据，不能通过跳过检查或吞异常使测试通过。

统一接口的输入输出 schema 与真实处理函数结果一致；使用同一数据验证页面调用与共享入口返回同一业务结果。跨应用联调验证调用方声明 apps.read/appAccess 后成功，缺依赖、缺目标角色、目标停用和撤权时拒绝。仅向 apps 开放的接口在开发目录可见，但个人 /call 必须拒绝。开放处理器中的平台写入和继续跨应用调用也须拒绝。

AI 相关改动验证缺少配置、模型不可用、非法模型参数、用户取消和合法草稿。无模型环境时用受控替身完成代码验证，并报告真实模型测试尚未执行。草稿生成不得写入正式业务数据。

## 页面与平台联调

本地平台用 `MOP_DEV_APPS_DIR` 指定开发目录，应用运行 `npx --no-install mop-app dev --out <同一目录>`。仅非生产平台支持自动安装。负责人配置测试员工的业务角色与范围后，实际执行页面操作。涉及页面布局时核对窄屏、明暗主题、加载、错误和空状态。

没有本地平台时完成单元测试与打包，在隔离测试实例中安装包进行上述联调。不得为联调擅自使用生产写入或扩大角色权限。安装新包后重新查看接口目录，确认显示的应用版本与本次交付一致。

## 交付证据

记录命令结果、应用版本、产物路径和实际测试环境。明确哪些是模拟 gateway 测试、哪些是已安装平台的操作验证。列出尚需验证的真实模型、业务角色或外部系统行为。平台升级与应用包升级分别进行，打包通过不表示生产已更新。
