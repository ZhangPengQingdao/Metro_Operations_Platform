# 应用接入

业务功能以独立应用接入平台。应用是一个 `.mopkg` 文件：`app.json`、图标、页面（`ui.js`/`ui.css`）、接口（`server.js`）和数据表迁移。开发步骤见 [开发者指南](developer/start.md)，设计见 [应用模型 v2](app-model-v2.md)。

## 平台配置

启用应用管理需设置 `MOP_APP_MANAGEMENT_CONFIG` 为一个 JSON 文件的绝对路径（模板 `config/app-management.example.json`）：

```json
{"version": 1, "artifactRoot": "/srv/metro/packages", "uploadRoot": "/srv/metro/uploads"}
```

安装包按版本解压到 `<artifactRoot>/v2/<appId>/<sha256>/`。1.0.0 之前的配置项（`runtimeRoot`、`publisherPolicyFile`、`approvedManifestDigests`、`managedStorage`、`docker`）仍被接受但不再使用。数据库方面，API 数据库角色需要该库的 `CREATE` 权限，以便安装时为应用创建 schema（`app_<安装ID>`）。

## 安装、升级与停用

管理员在“应用管理”：

- **安装应用**：上传 `.mopkg`，预览名称、图标、版本变化、权限与平台能力、页面、接口、迁移和问题清单后安装。平台创建数据表、授予 `app.json` 申请的平台能力并启动应用。
- **更新**：上传更高版本。平台停止旧版本、执行新增迁移、切换版本、重新授予平台能力并启动。同版本只在应用停用时作为“修复”接受，更低版本拒绝。
- **启用 / 停用**：停止或启动应用进程，数据和授权保留。
- **状态**：查看后端进程状态、自动重启次数、上次退出原因和最近日志；应用已启用但没有运行时可“重新启动”。
- **授权**：指定应用负责人，查看和调整平台能力。

## 负责人与员工

管理员指定应用负责人后，负责人在员工端“应用管理”配置使用人员、业务角色和每个权限的数据范围，见 [应用负责人与业务授权](application-business-authorization.md)。员工具备生效的业务角色才能在侧栏看到应用；安装或授予平台能力不会自动对所有员工开放。

员工可以在员工端“应用管理 → 申请上架”提交 `.mopkg`；负责人可以提交已有应用的更新包。管理员审核时看到与安装相同的预览，批准后直接安装。相同请求与相同包不会创建重复申请；单人最多 100 条申请、全部申请包累计不超过 512MiB。安装结果不确定的申请标记为“需核对”，不会自动重试。

## 运行方式

- 页面在平台内同源渲染（不是 iframe）。平台提供页头、标题、侧栏、主题、提示与确认框；页面共享平台的 React 与组件库。
- 每个启用的应用由 API 进程以 Node 子进程运行，环境变量只有 `NODE_ENV`、`TZ`、`PATH`、`MOP_APP_ID`，不含数据库地址或密钥；所有平台能力经父进程以应用的服务身份执行。异常退出按 1s→60s 退避自动重启，5 分钟内连续 5 次后停止，管理员可在“状态”中重新启动。
- 每个应用默认内存上限 256MB（`app.json` 的 `limits.memoryMiB` 可调），接口超时默认 30 秒（`limits.timeoutSeconds`）。
- 应用数据写入以事务和 `requestId` 保证：同一请求重试返回第一次提交的结果，不会重复写入。

## 仓库内的应用

`applications/` 下的故障记录、检修管理、待办事项、隐患提报、在线签字、慧策通、晨会交接、物料管理均为 `.mopkg` 项目，在各自目录运行 `npm test`、`npm run build`。业务说明见各应用 README。
