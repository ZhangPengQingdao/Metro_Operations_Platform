# 线路与车站

管理员进入 **基础数据 → 线路与车站**。页面包含“车站”和“线路”两个标签，沿用共享 L2 筛选、列表、分页和弹窗组件。原 `/admin/data/lines`、`/admin/data/locations` 页面地址自动转到此页。

## 管理方式

- 先在“线路”标签建立或启用线路，再新增车站。
- 车站维护名称、简称、状态，以及一条或多条所属线路。每条线路分别填写站序（1–100000），同一线路不能重复站序。默认建议当前最大站序加一；插入或调整既有站序时先解决占用。
- 换乘站使用同一份车站资料和同一个车站 ID，添加多条线路。多个工班可以在 **组织与工班 → 管辖车站** 分别选择同一个车站；工班管辖与线路归属独立。
- 车站列表、表单不显示上级位置和所属组织。编辑既有车站保留其原有层级、组织字段和 ID，不改写故障、隐患、资产或责任范围引用。
- 停用线路可以保留既有归属或移除归属，不能向它新增车站或调整站序。车站至少关联一条线路；停用车站及停用线路不出现在员工应用的有效管辖候选中。
- 搜索覆盖全部车站名称、简称、关联线路名称。按线路、车站状态筛选，每页 50 条。

## 管理员 API

以下接口需要独立管理员会话，写入要求规范 Origin，不能使用员工或应用身份。响应包含可用于并发检查的 `revision`。

| 方法与地址 | 用途 |
| --- | --- |
| `GET /api/admin/data/line-stations?q=&status=&lineId=&page=1` | 读取线路选项和分页车站目录，返回 `lines`、`stations`、`total`、`page`、`hasNext` |
| `POST /api/admin/data/stations` | 新增车站及线路关系 |
| `PUT /api/admin/data/stations/:id` | 更新车站及完整线路集合，必须附带最新 `revision` |

保存字段为 `name`、`shortName`（可空）、`status`（`active` / `inactive`）和 `lines`（1–50 条 `{lineId, sortOrder}`）。禁止客户端指定编码、上级位置或组织。编码由系统生成，保留已有线路关系的 ID 和编码。

保存与管理员审计在同一数据库事务内；目录写入序列化，并通过唯一约束校验线路关系。`STALE_REVISION` 返回 409，需要刷新后重新核对；占用站序等输入错误返回 400。网络中断或响应不完整时不自动重试写入，先刷新核对当前结果。

底层沿用 `platform_locations`、`platform_lines`、`platform_line_stations` 的多对多模型，无新增迁移。非车站位置及既有通用目录 API 继续保留给资产、公共能力和现有集成使用。
