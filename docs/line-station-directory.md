# 线路与车站

管理员进入 **基础数据 → 线路与车站**。页面包含“车站”和“线路”两个标签，沿用共享 L2 筛选、列表、分页和弹窗组件。原 `/admin/data/lines`、`/admin/data/locations` 页面地址自动转到此页。

## 管理方式

- 先在“线路”标签建立或启用线路，再新增车站。
- 车站维护名称、简称、状态，以及一条或多条所属线路。每条线路分别维护车站编号：可留空后补；1–50 位字母、数字、点、下划线或连字符，以字母或数字开头，保留前导零。同一线路内不区分大小写唯一，不同线路可重复，停用车站仍占用该线路内的编号。换乘站在不同线路上可有不同编号。
- 每条线路分别填写站序（1–100000），同一线路不能重复站序。站序仅用于线路内排序，与车站编号独立。默认建议当前最大站序加一；插入或调整既有站序时先解决占用。
- 换乘站使用同一份车站资料和同一个车站 ID，添加多条线路。多个工班可以在 **组织与工班 → 管辖车站** 分别选择同一个车站；工班管辖与线路归属独立。
- 车站列表、表单不显示上级位置和所属组织。编辑既有车站保留其原有层级、组织字段和 ID，不改写故障、隐患、资产或责任范围引用。
- 停用线路可以保留既有归属或移除归属，不能向它新增车站或调整站序。车站至少关联一条线路；停用车站及停用线路不出现在员工应用的有效管辖候选中。
- 搜索覆盖全部车站编号、名称、简称、关联线路名称。按线路、车站状态筛选，每页 50 条。

## 管理员 API

以下接口需要独立管理员会话，写入要求规范 Origin，不能使用员工或应用身份。响应包含可用于并发检查的 `revision`。

| 方法与地址 | 用途 |
| --- | --- |
| `GET /api/admin/data/line-stations?q=&status=&lineId=&page=1` | 读取线路选项和分页车站目录，返回 `lines`、`stations`、`total`、`page`、`hasNext` |
| `POST /api/admin/data/stations` | 新增车站及线路关系 |
| `PUT /api/admin/data/stations/:id` | 更新车站及完整线路集合，必须附带最新 `revision` |

保存字段为 `name`、`shortName`（可空）、`status`（`active` / `inactive`）、`lines`（1–50 条 `{lineId, stationNumber, sortOrder}`）和 UUID `requestId`。每条线路的 `stationNumber` 首尾空白会去除，传 `null` 清空，更新时省略保留该线路原值；空字符串无效。列表和保存响应在 `lines[]` 内返回 `stationNumber`，旧关系为 `null`。禁止客户端指定内部 `code`、上级位置或组织。内部编码由系统生成，保留已有线路关系的 ID 和编码。停用线路可保留或移除，不能修改其编号或站序。

保存、管理员审计和请求幂等结果在同一数据库事务内；目录写入序列化，并通过唯一约束校验编号和线路关系。`DUPLICATE_STATION_NUMBER`、`STALE_REVISION` 返回 409，需要核对编号或刷新后重新编辑；占用站序等输入错误返回 400。同一请求编号、管理员及参数重复提交仅返回首次结果，不覆盖后来保存的配置；请求编号被用于其他参数时返回 `REQUEST_ID_REUSED`。网络中断或响应不完整时不自动重试写入，先刷新核对；同一弹窗内原样手动重试沿用请求编号。

1.8.1 新增 `platform-station-number-expand` 迁移，在 `platform_line_stations` 新增可空 `station_number` 和线路内唯一约束，并建立 `admin_station_requests` 幂等记录表。旧线路关系的编号留空，内部编码、车站 ID、线路站序、工班管辖和历史业务引用保留。正常发布后在管理端点击在线更新，更新器会在备份后自动执行迁移，无需手动运行数据库命令；源码开发或手工部署才需自行执行 `db:init`。

本次仅开放管理员维护及管理目录搜索。应用 SDK 的目录字段和员工权限沿用现有契约；业务应用仍按车站 ID 引用车站。
