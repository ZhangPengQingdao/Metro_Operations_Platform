# 应用负责人、业务角色与数据范围

## 管理边界

平台管理员在应用授权中指定一位在职员工为应用负责人，也可撤销或更换。负责人可在该应用的「应用管理」中管理全平台人员的本应用角色，不受本人部室/工班限制。负责人身份不自动获得业务数据权限；需要使用业务功能时，仍须分配业务角色。

应用启停、升级、发布者信任与平台能力授权仍由平台管理员管理。岗位用于人员组织信息，不自动产生应用角色。一个人只有一个岗位，但可在每个应用内分配多个角色；同一操作的数据范围按角色取并集。应用之间的角色与分配互不通用。

## 使用步骤

1. 执行平台数据库初始化命令，安装 `app-business-authorization-expand` 迁移；正常启动不自动迁移。
2. 平台管理员在应用授权中保存负责人。
3. 负责人用员工账号登录，进入该应用侧边栏的「应用管理」。应用须已启用。
4. 新建业务角色，为每项操作选择范围，向人员分配角色。
5. 核对角色和人员后，明确确认「切换授权方式」。切换前保持旧授权；切换后旧全局业务角色和员工使用名单不再授予该应用业务权限。没有业务角色的负责人仍能管理授权。

不会自动把岗位、旧工班长规则或旧物资管理员名单转换成新角色，也不推测其等价范围。切换前应逐人核对；界面中的人数只是配置统计，并非迁移等价性证明。切换没有一键回退入口。

## 保存反馈

人员管理保存人员范围、批量分配角色成功后自动关闭当前弹窗，并在应用管理页显示保存结果。新增或修改角色成功后关闭角色编辑窗并返回角色列表。人员列表中的单人角色选择属于即时操作，成功后刷新当前列表并显示结果，便于继续配置其他成员。

提交期间显示保存状态并禁用重复提交；只有服务端确认成功才关闭。保存失败或 revision 冲突时保持弹窗打开并显示错误，未知响应仍须先重新读取核对，不能自动重放。

## 范围

| 范围 | 含义 |
| --- | --- |
| 本人 | 应用定义的资源归属人等于当前可信人员 ID |
| 本工班 | 当前人员所属工班 |
| 本部室及下属工班 | 当前人员所在部室及其下属组织 |
| 指定组织 | 显式选中的组织，不自动包含下级 |
| 全平台 | 本应用该操作的全部业务资源 |

范围支持由应用清单声明。未声明范围的旧操作只支持全部，不会把未支持的本人/组织范围当作全部。单次解析最多包含 128 个工班、每项操作最多 127 个组织，超过上限明确拒绝，不截断或放宽。组织变动、角色停用、人员离职及撤权在后续请求中重新核对；进行中的 API 调用和托管写入提交保护还会检查授权快照是否变化。

## SDK 与应用责任

清单 `permissions.defined[]` 可声明 `scopeKinds`。API 可声明 `businessPermission` 关联该操作；需在内部根据请求细分操作的入口可声明 `businessEntry: true`，两者不能同时使用。入口只说明允许进入后端，不能代替资源授权。

应用通过公开 SDK 的可信 `employee.businessAuthorization` 获取操作、解析后的组织 ID 与授权版本；使用 `allowsAppResource(employee, permission, {organizationUnitId, ownerPersonId})` 校验资源。身份与范围来自宿主，不接受网页请求体传入的人员或范围。

列表使用 `AppDataListOptions.anyOf` 表达组织或本人条件的并集，服务端先过滤后分页。写入前校验操作和原资源归属，关联库存按原资源组织维护；不能用请求传入的组织或修改者替换原记录归属。新增应用也须实现并测试自己的资源语义，签名安装并不会自动为业务表生成行级权限。

独立授权只替代本应用业务角色判断，不授予平台管理权限、不扩展应用服务身份的目录/存储权限。调用平台能力仍使用平台授予的能力与原 Gateway 检查。

## 物料应用

物料 0.2.x 接入库存查询、消耗查询、新建物料、修改物料、入库、出库、修改消耗、删除消耗。新建物料包含初始库存；入库还包含入库记录的调整。本人库存范围对应物料创建人，本人消耗范围对应原记录操作人（不是领用人）；代修改仍保留原归属。

建议按实际职责创建角色：普通成员查询本工班库存/消耗、在本工班出库、修改/删除本人消耗；工班管理角色在本工班入库和管理记录；部室角色使用本部室范围。它们是负责人可配置的示例，不是按岗位自动下发的内置规则。新模式下原应用「设置/物资管理员」入口关闭，统一使用应用角色管理。

## API

- 管理员 GET/PUT `/api/admin/apps/:appId/owner`：负责人和配置版本；PUT `{personId,revision}`，首次 revision 为 null。
- 员工 GET `/api/employee/managed-apps`：本人负责且启用的应用。
- 负责人 GET `/api/employee/apps/:appId/business-authorization`：角色、成员、范围声明、模式、版本。
- 负责人 GET `/api/employee/apps/:appId/business-directory?search=&page=1`：在职人员和启用组织，不返回手机号等联系字段。
- 负责人 POST `/api/employee/apps/:appId/business-authorization`：`action` 为 role/member/activate，必须携带当前 revision；旧版本返回冲突。角色/人员/切换均写入审计。未知响应先重新读取核对，不能自动重放。
