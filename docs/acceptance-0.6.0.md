## 本地实际操作

1. 停用现有验收物料应用，显式执行平台迁移，重启该项目 API。
2. 使用已信任开发者签名，通过预览、批准、升级、服务身份准备与授权、启用流程升级至物料 0.2.1，再升级至最终包 0.2.2；原库存和流水保留。
3. 指定验收工班长为负责人，创建工班业务管理及普通成员角色，明确切换应用独立授权。
4. 负责人未分配业务角色时，应用管理可访问、业务应用列表为空；分配后可查询本工班库存，修改/删除本工班消耗。
5. 普通成员访问应用管理返回拒绝；外班人员查询库存为空；撤销普通成员角色后列表移除应用、页面资源入口返回 403。验收后恢复该成员分配。
6. 新建专用验收物料，初始库存 10；普通成员出库 2，修改为 3，再删除该消耗，库存恢复 10。原流水及冲销记录保留，没有删除审计证据。
7. 浏览器验证角色编辑及保存、切换确认、实际消耗操作按钮；检查浅色、深色、390px 窄屏角色弹窗。共享 L2 筛选默认值引发的重复渲染已在源头修复。

### 重置后补建能力授权（2026-09-18）

重置后员工访问应用报「没有此操作权限」：员工业务授权（application 模式）本身正常，根因是安装记录 `record->'grants'` 为空——重置流程没有重建 service 模式能力授权，网关对 `platform.app_data.*` 的 `context.authorize` 找不到 active grant 返回 403，应用信封映射后即表现为无权限。修复：以管理员对清单 `permissions.requested` 逐项补建（`POST /api/admin/apps/materials/grants`，`mode:'service'`、`serviceIdentityId` 取安装记录、`scope:{kind:'all',targets:[]}`），涉及 `platform.app_data.read`、`platform.app_data.write`、`platform.people.read` 三项。注意：每次授权都会递增安装 revision，而运行中的 host 在激活时钉住了 `active.revision`，任何 revision 变化都会使 `admittedSnapshot` 拒绝准入（`/ui` 报 ACCESS_DENIED）——因此补完授权必须 disable→enable 一次让 host 重新激活，前端页面也需刷新获取新 admissionKey。
