# 慧策通 2.4.1 授权读取恢复与诊断

2026-10-31。针对月度计划页面同时显示“读取失败，请重试”和“正在读取员工授权…”的反馈。本次修改仅在独立慧策通应用中，平台版本保持 1.8.1；应用版本为 2.4.1，无数据库迁移和新增权限。

## 原因与证据边界

代码确认授权初始化请求 `session` 失败时只设置通用错误文本，`session` 仍为空；渲染将“为空”一律当作“读取中”，没有失败状态或重试按钮。因此任意一次失败都会持续显示加载提示，用户必须切页或刷新恢复。后端 handler 又将非业务异常统一压成 `READ_FAILED`，既不显示原始公开错误码，也不记录应用内部的异常定位信息。

授权初始化逐个读取授权组织的层级，再读取部门工班。同一请求中，自己及已查到的祖先仍可能重复调用；列表初始化的两个状态重置 effect 还会把 `[null]` 分页游标反复换成新数组，触发多余的读取。

只读核查生产 API 容器在北京时间 20:10–20:25 的日志和技术审计：慧策通组织层级查询成功 27 次、工班查询成功 4 次，未记录该时间窗内的网关失败。当天另有一次 `platform.app_data.list` 的拒绝发生在 16:16，与截图时间不同，不能当作本次原因。应用可能以 HTTP 200 返回 `{ok:false,error}`，所以 HTTP 状态成功也不能证明应用调用成功。现有诊断不足以证明本次最初失败来自权限、限流、数据库或网络，未修改真实账号授权、调用生产写接口或部署。

## 修复

- 授权读取区分加载、成功和失败。失败停止“读取中”提示，显示独立的“重新读取授权”按钮；每次重试重新向服务器获取授权，不沿用旧成功结果。
- 授权与列表请求传递取消信号；离开页面、切换查询时取消旧请求，迟到结果不写回当前状态。真实拒绝和空部门授权仍明确提示，不放宽后端鉴权。
- 保留允许公开的访问拒绝、限流、忙碌、超时、审计未确认、网关失败错误码。授权失败附平台注入的请求编号；日志只记录事件、公开代码、请求号和错误类型，不记录正文、个人资料、令牌或异常私有消息。未知异常继续使用 `READ_FAILED`。
- 同次 session 读取复用已授权查得的祖先路径，去重工班；不跨请求、跨员工缓存授权，不用上级部门工班清单推断子部门归属。测试中的重复祖先组织场景，层级调用由 4 次降为 2 次，工班读取仍为 1 次；不代表线上整体提速比例。
- 已是初始分页游标时不重复重置，避免相同列表请求重复发送。没有全局请求自动重试，也没有自动重放写入。

## 验证与交付

- 慧策通单测 42/42，通过新增祖先复用、跨请求不缓存、子部门归属不变、诊断脱敏、错误码和未知写入结果测试；平台相关集成 8/8 通过。
- 前端类型检查、SDK/CLI/开发者资源/平台前端构建、API 构建及应用 check/build 通过；应用包版本为 2.4.1。
- 生产构建的真实平台前端加载实际 `.mopkg` 内的 UI 资源，以受控 API 响应验证：首次 session 失败后无加载提示、无自动重试和业务读取；手动重试成功后只读取一次列表；真实拒绝保留；切页取消及迟到失败隔离；桌面与手机明暗布局。浏览器页面异常 0，业务写入 0。脚本与截图在本地忽略目录 `output/playwright/hct-auth-*`。
- 自查错误处理、权限范围、取消、未知写入、异常脱敏与请求数量；本次没有平台接口或数据库结构改动。

生效需要在管理端「应用管理」上传并升级 `huicetong-2.4.1.mopkg`。仅更新平台版本不会自动更新慧策通独立应用包。当前尚未提交、发布或安装到生产。后续若再遇到读取失败，可用页面请求编号对应 `hct.session.failed` 日志与网关审计继续定位；`READ_FAILED` 且无网关失败时，应优先查看应用日志的异常类型，再按实际证据进一步修复。
