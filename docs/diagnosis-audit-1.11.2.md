# 应用刷新 AUDIT_FAILED 诊断

日期：2026-11-02。用户截图为慧策通月度计划加载阶段，错误码 AUDIT_FAILED，页面请求编号 32c3b8f8-96d4-45a4-b45d-60c69b3b4d89。

授权初始化调用 platform.people.organization_context 和 platform.people.workgroups；每次网关操作完成后必须确认技术审计写入。旧实现把原本用于超时后收尾的 100ms 宽限同时用于正常审计。数据库连接排队、IO 或事件循环延迟均可能触发误判，实际 INSERT 仍可能稍后成功。

本地将正常审计延迟设为 300ms、请求总时限设为 1500ms，旧实现稳定返回 AUDIT_FAILED；修改后正常成功，且只写入一次审计。相同延迟下真正的权限拒绝仍返回 ACCESS_DENIED，不执行业务操作。

修复：正常操作与失败操作的审计使用请求剩余总时限；请求超时或取消后，最多再等 100ms。审计确实失败或迟迟未确认仍拒绝成功响应，未完成的审计继续占用并发槽并参与排空。对进入网关前就已取消的请求也启动收尾流程。

日志新增 app.gateway.audit_failed，包含 reason（storage/timeout）、应用、操作、网关请求编号、员工请求编号及允许格式的存储错误码，不记录 SQL、参数、凭证或原始异常文本。可用截图中的员工请求编号关联后续故障。

生产只读 SSH 两次均被远端关闭，未取得该请求对应的现场日志或数据库耗时。因此已经复现并修复代码中的确定缺陷，但不能据此断言截图这一次必然由超时而非数据库写入异常引起。未修改生产配置、业务数据或部署。修复属于平台网关，无需单独修改慧策通应用包。

验证结果：平台 551/551 测试通过，其中网关 21/21。SDK、CLI、开发资料、前后端构建、前端类型检查与 1.11.2 版本一致性检查通过。本次不涉及页面改动，复现与验收使用网关实际执行路径及可控审计延迟。
