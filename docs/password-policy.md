# 账号密码规则与首次登录改密

员工与管理员使用相同规则：密码至少 8 个字符，大写字母 `A–Z`、小写字母 `a–z`、数字 `0–9`、特殊符号四类中至少包含三类。特殊符号包括标点和符号；空格、换行、控制字符和中文文字不计作特殊符号。沿用 bcrypt 的 UTF-8 最多 72 字节限制；密码不自动裁剪或去除首尾空格。

例如 `Abcd1234`、`abcd123!`、`ABCD123!` 均符合规则；只有字母和数字的 `abcd1234` 不符合。员工注册、创建员工账号、管理员重置员工密码、创建管理员、首位管理员初始化及两种身份的本人改密都在服务端强制校验，网页和 Linux 安装器同步提示并校验。

## 已有账号

升级时不扫描或重写密码哈希。下次通过统一入口 `POST /api/auth/login` 或各身份的 `/auth/login` 成功验证密码时，系统检查本次输入的密码。不合规账号撤销已有会话，并签发带 `password_change_required` 的受限会话；登录响应的公开账号和对应 `/auth/me` 返回 `passwordChangeRequired: true`。

受限会话只允许本人读取 `/auth/me`、调用 `PATCH /auth/password` 和 `POST /auth/logout`。管理员与员工的 Cookie 路径分别为 `/api/admin` 和 `/api/employee`，身份继续独立。受限会话不参与管理员授权或员工身份解析；直接请求目录、资料、应用、通知、网关等接口会被拒绝。刷新页面或直接打开工作台也会显示强制改密表单。

改密接口接收 `{currentPassword,newPassword}`，继续核对当前密码、新密码规则、Origin 与有效身份。校验失败保留受限状态；成功后撤销该账号的全部会话、清除当前 Cookie 并要求重新登录。新的合规密码登录后恢复正常会话。

## 升级

前后端同步更新，先执行 `npm --prefix server run db:init` 应用 `platform-password-policy-sessions-expand`（`MIG-075`），再重启 API。迁移仅给两种会话表增加默认 `false` 的字段，保留账号、密码哈希及审计数据；重复执行不会覆盖会话标记。升级前已登录的会话继续沿用，密码规则在下一次登录时检查。
