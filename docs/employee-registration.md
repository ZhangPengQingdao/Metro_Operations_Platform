# 员工注册与审核

统一登录页提供“注册员工账号”。工号、姓名、密码和所属组织必填；手机号和企业微信 UserID 选填。工号采用现有登录账号格式（3–50 位字母、数字、点、下划线或连字符，首位字母或数字），登录按小写处理。密码至少 12 位，UTF-8 编码不超过 72 字节。

申请人从启用组织下拉列表中选择。公开接口只展示组织 ID、名称、父组织 ID，每次最多 100 项，不公开人员目录。滑块使用服务端生成的五分钟随机目标，一次性消费、校验目标和最短时间，并对挑战和提交限流。这是基础交互验证，不是强反机器人或身份认证；手机号和 UserID 也不视为已核验身份。

管理员在“账号与权限 → 注册审核”处理申请，通过前确认组织并指定启用岗位。审批事务一次性创建人员、员工账号、未核验的企业微信资料及审核审计。账号以工号登录；不会赋予应用访问权限或业务角色。已有工号人员不被覆盖：管理员应拒绝重复注册，并通过“创建员工账号”关联已有人员。审核通过与拒绝均清除申请中的密码哈希，保留申请资料和审核状态；拒绝后可以再次申请。

申请状态为 pending 时不创建员工账号，不能登录。重复申请、重放滑块、重复审核、停用组织/岗位和非管理员审核均拒绝；账号、人员或 UserID 冲突时事务回滚，申请仍待审核。密码原文不会落库或返回。

## API

- `GET /api/auth/registration/organizations?q=名称`：启用组织列表。
- `POST /api/auth/registration/challenge`：一次性滑块挑战。
- `POST /api/auth/registration`：提交工号、姓名、组织、密码、可选联系方式及挑战答案。
- `GET /api/admin/registrations?page=1`：待审核申请，每页 20 项。
- `POST /api/admin/registrations/:id/review`：`reject` 或 `approve`；通过须指定 organizationId、positionId。只接受原生管理员会话，写接口校验 Origin。

升级后先执行 `npm --prefix server run db:init`，应用 `employee-registration-expand` 增量迁移，再重启 API。该迁移不导入旧数据，不更改现有账号与应用权限。
