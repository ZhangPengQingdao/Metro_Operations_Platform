# 故障记录应用：原功能核对与首版设计

状态：首版已在云端签名安装；0.0.2 的搜索选择控件及设备目录接入待更新验收。本文记录业务行为与尚待接入的能力；新应用独立保存数据，不读取旧系统的数据库、源码或运行时。

## 原系统实际功能

核对了故障页面、表单、故障接口、数据完整性与导出逻辑。原故障页的能力如下：

| 区域 | 原系统行为 | 首版目标 |
| --- | --- | --- |
| 查询 | 默认看未修复；切换全部、未修复、已修复、待完善；按发生日期、车站筛选，按发生时间正倒序；显示数量、设备、接报/处理人和状态 | 保留。列表按业务权限过滤组织，服务端分页，不能只在浏览器中过滤越权数据 |
| 新增 | 手工填写接报时间、接报人、所属工班、处理人、车站、设备类型及编号、现象、原因、处置措施、到达/修复时间、是否工电倒切、修复状态 | 保留字段和手工新增。所属工班取可信员工身份或其获授权的组织，不能凭表单文字指定数据归属 |
| 编辑与闭环 | 编辑记录、切换未修复/已修复；校验时间顺序；已修复时检查到达和修复时间 | 保留。修复状态通过完整表单保存，修改后重新读取记录；重新打开为未修复时清除修复时间 |
| 删除 | 工班长或管理员可删除；删除前确认 | 保留操作，但应用内作废并留审计，列表隐藏作废项；仅有 `delete` 权限者可操作 |
| 小单录入 | 粘贴企业微信小单，按字段别名识别时间、地点、设备、人员、现象、原因、措施和状态，带入表单供人工核对；额外用 AI 和设备点表核对设备 | 首版至少保留粘贴、字段识别、回填和人工确认；AI/点表部分见“待接能力” |
| 导出 | 按起止日期导出权限范围内所有状态的 Excel，包含时间、车站、设备、人员、状态、原因、措施、工班、来源 | 保留按日期范围导出，服务端再次校验权限；文件字段与原表一致 |
| 数据质量 | 提示缺车站、设备编号不匹配、已修复记录缺接报人/处理人/到达时间/原因/措施、时间倒序等；有“待完善”筛选 | 必填字段与时间顺序在保存前拦截；已修复但缺原因或措施的记录进入“待完善”。设备点表匹配提示待平台目录能力接入 |
| 云文档同步 | 新增、修改后尝试同步，页面可批量补同步；删除时标记云端记录 | 属于外部集成，需明确目标云文档与平台受控能力后接入，不能以无效“同步”按钮代替 |
| 关联场景 | 交接班可批量创建并关联故障；首页统计未修复故障；提醒服务读取待完善和遗留故障 | 首版记录来源，跨应用关联 ID、录入和提醒在公开应用间契约明确后接入 |

原系统还有设备标准化、历史数据修复、企微来源去重等内部逻辑。新应用只对新写入数据做校验，不迁移或修复旧数据。

## 首版页面与流程

只设一个“故障记录”入口，包含列表和新增/编辑弹窗；不设独立设置页。

1. 进入时默认显示本工班未修复记录。L2 筛选面板可切换未修复、已修复、全部、待完善，筛选日期与工班，并调整发生时间排序；搜索可查询车站、设备与故障文字。搜索、筛选、新增入口靠右；导出和小单粘贴在功能菜单内。
2. 新增时先确定业务组织（单工班员工自动确定；获跨组织授权者才可选择），再填写故障。保存成功显示记录；结果未知时保留表单和请求编号，要求先核对，不自动重发。
3. 处理人通过一个搜索下拉框从在职人员目录选择。接报人默认当前填写人，允许改为文字以容纳电话/外部来报；另存可信的创建人 ID。
4. 车站、设备类型和设备编号均可在同一输入框内搜索或展开选择；目录无数据时仍可手工填写。设备编号候选限定在已选择的目录车站及类型，手工录入不宣称点表已匹配。
5. 未修复记录补齐处置信息后标记已修复。修改保留创建人和原组织；跨组织移动不作为普通编辑。
6. 只有具备删除权限者看到作废操作；作废需二次确认并记录操作者、时间。导出不包含已作废记录。

### 字段与规则

必填：接报时间、接报人、处理人、车站、设备类型、设备编号、故障现象、状态。选“已修复”时增加到达时间、修复时间；原因与处置措施缺失显示“待完善”。时间满足接报 ≤ 到达 ≤ 修复。工电倒切为“是 / 否 / 未确认”。来源为手工或小单粘贴，不接受网页伪造“企微自动导入”。

业务记录保存组织 ID、创建人 ID、处理人 ID，以及车站目录 ID（如有）和当时的名称快照、设备类型名称与编号。目录后来改名不改变历史显示；重新选择已有车站 ID 时核对目录。记录还保存版本号、创建/更新时间、作废信息，用于并发编辑和审计。

## 角色与权限

使用平台应用业务授权，应用负责人由平台指定；平台管理员身份不等于员工业务身份。岗位名称只用于建议分配，后端只认本次可信员工身份和已生效的应用权限。首版定义五项权限：

| 权限 | 含义 | 普通成员建议 | 工班负责人建议 |
| --- | --- | --- | --- |
| `app.faults.read` | 查看、筛选、详情 | 本工班 | 本工班 |
| `app.faults.create` | 新增、粘贴小单后保存 | 本工班 | 本工班 |
| `app.faults.update` | 编辑、修复、重开 | 本工班 | 本工班 |
| `app.faults.export` | 按日期导出 | 本工班 | 本工班 |
| `app.faults.delete` | 作废记录 | 不授予 | 本工班 |

如果需要跨工班业务人员，由应用负责人单独授予“指定组织”或“本部室及下属工班”范围；负责人身份本身不带上述权限。本人范围按记录创建人计算。读取、导出、编辑、作废都校验原记录组织；新增校验目标组织。应用启停、安装、服务权限仍由平台管理员管理。

原系统检修工可编辑同工班记录，工班长还可删除。本设计保留这一操作差异，但用可配置应用权限替代硬编码角色名称。

## 技术边界与待接能力

新应用参照晨会交接、物料管理的独立结构：沙箱界面、隔离后端、公开 SDK、应用自己的托管存储迁移。界面使用共享 L2 组件和中性主题。应用只通过公开 Gateway 读取在职工班成员、位置、设备；不导入平台内部模块，不依赖旧系统。

| 能力 | 现有平台接口与缺口 | 设计处理 |
| --- | --- | --- |
| 车站 | `platform.locations.list/get` 可分页读取授权位置 | 只展示有效车站，保存 ID 与名称快照；列表及导出按记录组织再次过滤 |
| 设备 | `platform.assets.list/get` 可查设备、类型 ID 与位置，但`assets.list` 已补充类型名称并支持名称搜索；当前没有独立的全量类型列表 | 从已登记且获授权的设备生成类型和编号候选；目录为空时手工输入，不做资产 ID 关联或点表核对 |
| 人员 | `platform.people.members` 可按工班搜索在职人员 | 选择处理人后端重新验证；失效人员的历史记录仍显示保存时的姓名 |
| 日期查询/导出 | 托管存储 `list` 已支持时间范围、排序和游标 | 按发生时间正倒序查询；导出分页读取，单次最多 5000 条，超限明确提示分段导出，不能静默截断。平台 0.13.0 起允许签名沙箱显式申请用户触发的文件下载 |
| AI 核对 | 当前应用 Gateway 无通用 AI 设备核对操作 | 本地规则解析后只给候选和“待人工核对”；若首版要求 AI 核对，需先提供受控平台能力 |
| 云文档同步 | 隔离后端默认不允许外联，也没有故障云文档写接口 | 确认目标文档、字段和鉴权后建立受控集成；此前不显示同步成功或补同步入口 |
| 交接班联动 | 现有晨会交接故障模块尚未写入独立故障应用 | 后续通过公开应用 API 和来源关联，不能让晨会直接写故障应用存储 |

## 实施与验收顺序

1. 已建独立应用清单、迁移、后端规则与列表/表单；用规则测试验证组织隔离、创建、编辑、闭环、作废和并发版本。
2. 已接车站名称建议与人员目录，完成小单本地识别、待完善筛选与 Excel 导出。仍需签名安装后以真实宿主和不同组织账号验收。
3. 后续按确定的外部集成范围接入 AI 核对与云文档同步，并对照旧页面逐项验收。

完成首版业务验收至少需要：普通成员只能看/改授权工班，负责人不因身份自动看到业务数据，跨工班授权有效；新建未修复→补全→修复→重开与时间校验正确；作废不出现在列表和导出；小单解析错误能人工修正；导出无越权、无截断；未知写入不自动重放。测试和构建通过之外，还需在实际员工沙箱检查表单、筛选、窄屏布局和导出文件。
