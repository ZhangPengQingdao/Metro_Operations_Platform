# 应用接入收尾工作记录

用户已确认首个真实应用为原 AFC 的物料管理：物料目录、入库、出库、库存和记录查询。旧项目仅作字段/规则参考，不引入源码路径或运行时依赖。不迁移旧数据，不继续服务器/1Panel 适配。

## 交付顺序与验收

1. 员工账号管理、登录、可用应用列表与沙箱身份通道。应用使用授权独立于员工角色/数据范围；撤权、离职、停用需在调用与返回前复核。已交付给浏览器的数据不能追溯撤回；页面失效提示通过轮询刷新，接口必须即时拒绝后续访问。
2. 物料所需通用目录分页/搜索与最小业务入口。业务规则放在应用，平台接口逐条校验返回记录范围，不接受客户端身份或直接数据库连接。
3. 托管存储：分页查询、原子多行操作、乐观/悲观并发控制、增量结构迁移、未知写入/迁移原事务证据核对、受限存储管理代理。物料出库不可用多个独立单行请求拼接；库存与出入库记录必须同一事务，负库存拒绝。
4. 发布者信任、版本审批、上传包预览、权限/资源/升级差异、安装/授权/运行分离展示，审批与每次启用复核。
5. 独立物料应用：旧字段参考为名称、SKU、单位、库存、领用数量/人/备注/时间、工班。新入库流水及出库事务必须有操作人和不可重放请求标识。用户已确认：保留原记录，通过关联冲销记录纠错；冲销入库时库存不足必须拒绝。不得编辑/删除原流水，不静默丢弃库存业务约束。
6. 独立 SDK/CLI 分发与签名 JSON 安装包，开发者不依赖平台后端源码；管理员只处理安装包。
