# 平台 1.7.2 页面稳定性与加载优化验收

2026-10-29。范围为平台员工/管理员登录恢复、员工应用切换与入口加载；不修改业务权限规则、数据库结构或应用包。

## 问题与处理

- 应用页面原先在路径更新时保留旧 `loaded` 会话，同时用新路径重建错误边界，导致旧页面再次挂载并发送旧参数请求。现在以应用、版本、运行修订号、路径和重试次数隔离页面实例，新会话就绪前仅显示加载状态，晚到响应不覆盖当前页面。
- `/apps` 和 `/managed-apps` 原先必须一起成功，任一失败即清空应用列表。现在独立加载并防止各自重入；暂时失败保留当前页面并显示重试，真实 401/403 或成功返回的撤权结果仍清除访问状态。每次业务请求继续受后端鉴权约束。
- 员工与管理员初次读取登录态失败时，原先因账号为空而直接跳回登录页。现在区分读取故障和确认失效，故障保留原地址并可重试。取消后的请求不能派发过时的登录失效事件或恢复旧账号。
- 员工 `/auth/me` 利用已有人员 JOIN 返回姓名，首次进入不再额外读取 `/profile`。完整资料仍在个人中心读取。
- Toast 上下文保持引用稳定，避免消息显示/消失导致应用 API 对象重建、触发应用的数据加载副作用。离开页面时未完成的确认按取消结算。
- 对话、工作台和应用管理改为按需加载。员工请求对网络中断及不完整响应保留未知结果，传递服务端 `writeOutcome`，不自动重放操作。

## 加载量与边界

同一构建环境下，用提交 `cbc4ddc` 的员工入口替换当前入口做对照，其余代码与依赖一致。计算员工入口及静态依赖闭包的 JavaScript 大小：由约 559 kB 降至 482 kB，约减少 **13.9%**；gzip 由约 174 kB 降至 152 kB，约减少 **12.6%**。工作台与对话合计约 19.3 kB 的样式也不再随业务应用入口加载。浏览器检查确认直接进入业务应用不会请求三个辅助页面的代码块。

这衡量的是代码加载量，不是生产接口耗时或端到端提速百分比。浏览器验证为故障注入场景，尚未使用用户账号复现线上全部偶发 403。若实际环境仍出现，应结合失败接口、错误码、时间与服务端日志定位授权版本、应用运行状态或数据库等待；不能通过放宽权限或重放写操作处理。
