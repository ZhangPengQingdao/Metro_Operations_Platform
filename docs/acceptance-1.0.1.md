# 1.0.1 应用业务流程验收

日期：2026-10-24。分支 `app-model-v2`，本地验收，未部署。八个应用均以 `.mopkg` 安装在临时平台（本地 PostgreSQL、开发应用目录自动安装），按真实员工登录、业务角色和数据范围逐个走业务流程；数据为验收示例数据。

## 验收环境

- 组织：一号线一工班（W1，负责甲站、乙站）、一号线二工班（W2，负责丙站）。车站通过工班管辖范围归属，设备不挂组织。
- 员工：张班长（W1，所有应用负责人，班长角色）、李值班（W1，成员角色）、王巡检（W2，成员角色）。
- 每个流程同时核对：本工班成员权限、班长权限、跨工班隔离（列表为空、详情/写入拒绝）、重复请求按 `requestId` 返回首次结果。

## 发现并修复的问题

平台：

- 应用接口调用平台签字、通知能力全部失败（`GATEWAY_FAILED`）：能力在自己的事务内做授权检查，授权查询使用独立连接却继承了调用方事务上下文，被事务一致性保护拒绝（`ATOMIC_CONNECTION_MISMATCH`）。授权查询改为在调用方事务之外执行。影响在线签字、晨会签字和签字通知。
- 签字留痕读取失败：`size_bytes` 为 BIGINT，node-postgres 返回字符串，映射只接受数字（PGlite 返回数字，测试未覆盖）。映射接受十进制字符串，测试改为模拟 node-postgres 行为。
- 应用网关把非预期异常统一转成 `GATEWAY_FAILED` 且不记录原因，无法定位。现在记录操作名与原始异常（应用仍只看到 `GATEWAY_FAILED`）。
- 暗色主题下选中标签、主色图标按钮、指标卡图标为白字白底。改用 `--afc-on-primary`。

应用：

- 故障记录、检修管理：设备列表按组织过滤，而设备不挂组织，列表恒为空。改为按所选车站查询，且只查本工班负责的车站。
- 检修管理：车站列表包含其他工班的车站，保存时也不校验。车站改取本工班管辖范围并在保存时校验。
- 隐患提报：v2 转换遗漏照片表迁移，照片上传失败。补 `002-photos.json`，测试核对迁移覆盖服务与照片存储使用的全部表。
- 待办事项：车站目标包含其他工班的车站。车站目录与保存校验改为本工班管辖范围；单项任务最多 50 个目标。任务列表每页只有 2 条（行内子项过大）：列表不再读取子项，每页 20 条，编辑时读取详情。
- 在线签字：“新建签字”按钮引用未定义的 `setRoute`，点击报错。改用平台导航；新增平台测试扫描所有应用源码中的未声明名称。
