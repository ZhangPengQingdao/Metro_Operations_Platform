# 应用管理与员工提交审核

## 当前实现

员工端“应用管理”使用与平台端相同的 L2 DataList、FilterBar 和 SVG 行操作组件。应用负责人通过行操作打开分栏设置弹窗，维护使用人群、角色及人员分配。应用内不再注入重复的负责人管理菜单。

员工可上传公开工具导出的 JSON 安装包申请上架；应用负责人可提交已有应用的更新包。员工只能查看自己的申请，平台管理员在应用管理的“上架与更新审核”中审核。服务器重新验证签名、可信发布者策略、已安装版本和存储兼容性；未获平台信任的发布者不会因提交申请而获得信任。

数据库增量迁移 `app-submissions-expand` 保存原包、提交人、审核版本、状态和审计记录。相同请求与相同包不会创建重复申请。不同包不得复用请求号。单用户最多保留 100 条申请，全部申请包累计上限 512 MiB；达到限制返回错误，不自动删除记录。

审核安装开始前持久化 processing 状态。执行结果不明时保留 uncertain；进程中断可能保留 processing，两者都禁止重新审核和自动重放。需先通过现有应用状态/恢复证据核对实际结果，当前没有自动清理这些申请的功能。

## 组织人员与单角色模型

应用列表只保留人员管理、角色配置、更新。人员管理使用公开 L2 `OrganizationPeoplePicker`：左侧多级组织树，右侧服务端分页成员，支持搜索与本页全选。组件不持有应用权限，也不自行读取平台接口。

负责人首次保存人员范围时，显式启用新模型并建立普通成员角色。未指定其他角色的范围内人员使用普通成员；普通成员的业务权限需要负责人配置，不会自动获得应用全部权限。普通成员不可停用或改名。

组织选择为动态规则：包含节点及其后代，可排除子组织或个人，排除优先于原有个人包含。负责人可在已排除的工班中重新勾选个人或本页人员；只加入明确选中的人员，不解除整个工班的排除，也不加入其他页或搜索结果以外的人员。再次取消该组织（或其上级）会清除其中重新勾选的人员。

`membership` 的 `audience.personOverrides` 是可选的 `{personId,organizationId}[]`，最多 1000 项，默认空数组；前端仅在重新勾选被组织排除的人员时填写。服务端验证人员当前组织，个人排除、组织停用及离职仍优先；人员调离后原组织的例外不再生效。旧配置未包含此字段时保留原有行为，无需数据迁移。组织调整、人员离职与范围变更在授权时重新核对。角色分配只显示范围内人员，允许逐人切换和最多 500 人的批量替换，每应用每人一条角色分配，数据库主键防止叠加。

迁移 `app-single-role-membership-expand` 是增量迁移，不自动改变既有业务权限。首次切换遇到旧多人多角色或已有工班委派记录会明确拒绝，保留旧规则，不能随机丢弃角色或自动扩权。旧通用委派接口在单角色模式下暂时拒绝，需后续将物料委派改为受约束的单角色切换。

## 平台安装审批与能力授权

平台授权弹窗仅管理负责人和平台能力，不再提供业务权限、人员范围或业务角色配置。新增业务授权通过平台 grants 接口会被拒绝；旧业务授权记录保留以兼容已有应用，不自动迁移或扩权。

安装预览展示申请的平台能力、访问身份和平台能力上限。管理员点击批准并安装/更新时，`install-approve` 明确提交 `platformCapabilities: true`，并将能力审批绑定到签名清单摘要。员工提交包的审核批准采用相同流程。配置导入和旧版本审批默认没有能力审批，不会自动获得授权。

首次安装在应用启动前准备服务身份、事务性授予声明的平台能力；升级在签名版本和存储迁移完成且应用停用后配置新身份与平台能力。带后端应用使用服务身份，无后端应用使用当前使用者身份并仍校验使用者的原有平台权限。当前支持应用数据读写、工班成员、位置与设备读取；未知平台能力拒绝批准。

授权事务失败不保留部分授权。安装/升级授权结果不确定时保留恢复状态，不自动重放。重复安装请求返回既有结果，不重新授予能力；日常启用不补回已撤销授权。升级需要管理员重新批准新清单中的全部平台能力，业务角色与范围始终由负责人独立配置。

## 当前验证

类型检查、SDK/前后端构建和版本一致性检查通过。完整回归 736 项通过、9 项环境跳过；后续新增平台授权事务测试通过。覆盖授权失败事务回滚、安装前授权、重复请求不重授、旧审批不扩权与升级停用状态下配置授权。

本地已应用 3 项增量迁移并重启 API。真实审核接口从 404 变为 200，负责人接口可用，平台新增业务授权被 400 拒绝。物料应用正常停用后恢复原有三项服务授权并重新启用，serving=true、pending=0。没有清除未知记录或重放未知创建。

本地真实签名验收包 `platform-approval-check` 已跑通预览、明确批准平台能力、安装、撤权、重复安装不重授、停用/启用不重授，以及新增设备读取能力的签名升级。验收版本 1.1.0 保持停用，专用发布密钥已撤销信任，审批和运行记录保留。该验收包不代表物料业务全链路验收。

## 状态界面

应用状态使用共享侧边栏弹窗分区展示。打开或切换分区重新读取，操作成功后自动更新；不提供常驻刷新按钮。系统更新保留自动进度查询；核对原事务与恢复为停用仍为独立操作，不会因读取页面而自动执行。L2 默认交互配色为中性色，语义状态色保留。

运行身份由平台内部维护：启用已停用应用时自动换发丢失凭据，原服务身份与授权保持不变，旧凭据失效；不向浏览器返回凭据。不对运行中或结果未知的操作直接换发。状态按操作显示“启动/停用/更新结果待核对”或“运行中断，待核对”，通过“核对并停用”完成证据核对后再启用；未完成调用继续阻断，不重放、不删除记录。
